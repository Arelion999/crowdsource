# Синхронизация новых строк

Скрипт `sync.py` подтягивает **новые** игровые строки из сервиса переводов и
заводит их в наш пайплайн (в `main_strings.csv` + свежие батчи `new/`).

## Настройка (один раз, локально)

Адрес сервиса **не хранится в репозитории** (он в `.gitignore`). Задай его одним из способов:

- переменная окружения:
  ```bash
  export GW2_SYNC_URL="http://<host>:<port>"
  ```
- **или** файл `sync/endpoint.txt` — одна строка с адресом (уже в `.gitignore`).

## Запуск

Запускай **после сдачи каждого батча**:

```bash
python sync/sync.py
```

- Сначала бьёт по `/count`. Если число строк не изменилось с прошлого раза —
  ничего не тянет и выходит (быстрый путь).
- Если изменилось — тянет `/list`, находит новые `english`-строки (которых ещё нет
  ни в `main_strings.csv`, ни в `dict_*.csv`, ни в `pn_*.csv`, ни в батчах),
  отсеивает нетранслируемое, дописывает их в `main_strings.csv` (пустой перевод),
  нарезает в `new/new_NNN.csv` (продолжая нумерацию) и обновляет `CLAIMS.md`.

Форсировать полный проход без учёта кэша:

```bash
python sync/sync.py --force
```

## Что коммитить

Коммить `sync.py`, `README.md`, `.gitignore`, новые `new/*.csv`, изменённый `CLAIMS.md`.
**Не коммить** `endpoint.txt` и `.state.json` (они локальные, уже игнорируются).
`main_strings.csv` лежит уровнем выше и в этот репозиторий не входит.
