# Склейка строк в игре: разделитель теряется на стороне мода

Отчёт для автора GlyphCore. Всё, что ниже, проверено по данным самого мода —
`dictionary.bin`, `lookup_cache.bin`, `discovered_strings.csv` — и по батчам
перевода. Правкой словаря класс не лечится: куски в словаре целые.

## 1. Что видно в игре

Тултип предмета склеивается на стыке соседних кусков — пропадает и пробел, и
перенос строки:

```
Облик разблокирован‸Длинный лук из мягкой древесины
Хорошее‸длинный лук
Требуемый уровень: 30‸Тип оружия недоступен вашей профессии
```

(`‸` — место, где должен быть разделитель.)

Воспроизводится на актуальной сборке словаря. Раньше то же самое видели на
сборке nourlie/GlyphCore — значит, от содержимого словаря не зависит.

## 2. Куски в словаре целые

Каждая половина шва — отдельная запись, и все они совпадают с показанным в игре
дословно:

| английский | перевод в словаре | на экране |
|---|---|---|
| `Skin Unlocked` | Облик разблокирован | Облик разблокирован |
| `Fine` | Хорошее | Хорошее |
| `Longbow` | Длинный лук | **д**линный лук |
| `Required Level: %num1%` | Требуемый уровень: %num1% | Требуемый уровень: 30 |
| `<c=#FF0000>Weapon type unusable by your profession.</c>` | …недоступен вашей профессии. | …недоступен вашей профессии |

Ломать внутри записей нечего: по всем **480 278** записям словаря число краевых
пробелов перевода совпадает с оригиналом — расхождений **0**.

Обратите внимание на третью строку: `Longbow` лежит в словаре с заглавной, а на
экран уходит со строчной. Значит, при подстановке кусок обрабатывается, а не
копируется как есть.

## 3. Улики: где именно пропадает разделитель

### 3.1. Ключи обрезаются по краям

| источник | строк | из них с краевым пробелом при непустом тексте |
|---|---|---|
| `lookup_cache.bin` | 728 | **0** |
| `discovered_strings.csv` | 363 | **0** (краевые пробелы есть только у 9 строк, целиком состоящих из пробела, — см. §3.2) |

Ни один ключ, который мод запомнил или собрал, не несёт краевого пробела. При
этом в самом словаре такие записи есть (` per day` → ` в день`, `\xa0today` →
`\xa0сегодня`) — они пришли из импортов, не из харвеста. Похоже, строка
обрезается перед тем, как стать ключом.

Если ключ обрезается, а подстановка накрывает **необрезанный** участок, разделитель
съедается ровно так, как на скринах.

### 3.2. Разделитель приходит отдельной строкой

Среди 363 строк `discovered_strings.csv` лежат **9 строк из одного пробела**.
То есть игра рисует разделители отдельными фрагментами, мод их видит, но в
итоговую сборку они не попадают.

Записей из одних пробелов нет ни в одном словаре (наш, community, nurli) —
переводить там нечего, значит подменять их не на что.

### 3.3. Английский, собранный модом, уже без разделителя

Это видно **без всякого перевода**. Сравнение английского из наших батчей с
`/v2/skills` по той же строке (сверка по тексту без пробелов) даёт **29** строк,
где у нас разделителей меньше, чем в API:

```
API   …granting might to allies and burning enemies. … burn foes.␣Using this skill…
у нас …granting might to allies and burning enemies. … burn foes.Using this skill…

API   …Strikes again after a delay.␣Shatter traits only affect…
у нас …Strikes again after a delay.Shatter traits only affect…
```

Тот же класс, но на стороне сбора: разделитель теряется ещё до того, как строку
кто-то переводит. Хеш при этом считается от огрызка.

### 3.4. Склейка застыла в самом словаре

Категория `выученные` — то, что прокси собрал на лету: хеш и перевод есть,
английского нет (145 записей из 425). У **78** из них шов без разделителя:

```
Добродетель: Регенерация здоровья.Активация: Бросается вперёд, исцеляя союзников…
Пассивный эффект печати: Улучшенный урон от состояний.Активный эффект печати: Оглушите врага.
Команда. Ударьте врагов…с основной цели на ближайших врагов.Эхо. Накладывает мощь…
-16%% входящего урона, пока оглушены…-10%% длительности входящих состояний+10%% опыта за убийства
```

Полный список с хешами — [GLUE_LEARNED.csv](GLUE_LEARNED.csv).

Разрезать их обратно нечем: ни у одной из 78 половинки шва не лежат в словаре
отдельными записями. То есть склеил не словарь — это выход самого мода,
записанный обратно в bin и раздаваемый всем.

## 4. Что просим проверить

1. **Подстановка.** Если ключ ищется по обрезанной строке, заменять надо тоже
   только обрезанный участок — краевые пробелы и переносы оригинала обязаны
   пережить замену.
2. **Сборка из кусков.** Между соседними фрагментами разделитель оригинала
   должен сохраняться. Фрагменты из одного пробела — тоже фрагменты.
3. **Харвест.** Строки, попадающие в `discovered_strings.csv` и в категорию
   `выученные`, теряют разделители (§3.3, §3.4). Хеш от такой строки в игре
   не совпадёт ни с чем — запись мертва, а испорченный текст расходится дальше
   по словарям.
4. **Регистр.** `Longbow` уходит на экран как «длинный лук» при записи в словаре
   «Длинный лук». Если это осознанная нормализация регистра в середине фразы —
   она должна знать про имена собственные; сейчас на этом же месте теряется и
   разделитель.

## 5. Что делаем со своей стороны

* 78 склеенных «выученных» вычищаем или переводим заново — это мусор от прежнего
  `online=true`, чинить по кускам нечем;
* 308 записей, где перевод потерял перенос оригинала, разбираем через
  `tools/seams.py` — это наш класс, к моду отношения не имеет;
* 263 записи с кириллицей в колонке `english` (разъехавшиеся колонки CSV)
  закрыты гейтом в `validate.py`, разбор — в [DEFECTS.md](DEFECTS.md).
